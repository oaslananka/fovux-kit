# Issue Lifecycle

Fovux issues follow a predictable lifecycle.

1. Triage: labels for type, area, priority, risk, and effort.
2. Ready: acceptance criteria and validation plan are clear.
3. In progress: implementation is active and linked to commits or PRs.
4. Waiting review: changes are pushed and validation evidence is attached.
5. Done/closed: issue is closed only after code/docs, tests, and quality gates pass.

High-risk protocol, security, API, release, or governance changes require an ADR before implementation.
